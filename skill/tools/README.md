# 工具清单（33 个，全部实装且带自检）

> **一条纪律**：这份表就是全部。手册里点到而这张表里没有的脚本，是死链，发现就删引用或补脚本——**不许留着让成员去跑一个不存在的命令**。

## 怎么进项目

`08_工具_脚本/开项目.py <书名>` 会把本目录整套脚本复制到新项目 `08_工具_脚本/`。
已有项目缺脚本：把本目录 `*.py` 复制进去即可。**不要**让 agent 直接调用技能目录里的脚本当项目脚本——项目内那份才是唯一入口（路径固定、审计可复现）。

**运行位置**：一律在**项目根目录**下跑。`选型体检.py`／`能力自测.py`／`状态体检.py` 不带参数，靠当前目录向上找 `项目配置.json`；在技能目录或别的书目录里跑，会报"读到 0 行""找不到根"——那是跑错地方，不是稿子有问题。要么先 `cd` 到项目根，要么显式给路径（`--file`／`--root`）。

## 三条使用纪律

1. **换机器先跑 `--selftest`。** 每个脚本都带自检；自检不过就别拿它判稿——坏工具判出来的"通过"比没有更糟。
2. **脚本是下限，不是上限。** 它们只抓语法层和可数的症状；"这一段有没有画面""读者会不会划走"必须人判。任何一次"脚本 PASS 但读起来要跳"，以人判为准，并把那条规则标成待修。
3. **改脚本要改这三处**：本表、`references/03-门禁手册.md` 的命令表、相关 agent 的必跑命令。三处不一致，成员会照着旧命令跑空。

## 已知不做（别去找）

- **文风指标**：1.36.0 起由 `文风靶.py` 实装，1.37.0 起九项 + 按档 + `--calibrate` 反推本书靶值。口径定死一条：**只出 CHECK，不进合门**——设成硬项就会有人凑数字，凑三轮门禁就成摆设。
- **环境细节**：不做独立脚本。看 `章指标.py` ＋ 人工核地标重复。
- **本地批注界面**：旧项目那套网页逐句批注工具，不在本包内；改稿走三条回路，不靠界面。
- **自动改稿**：不做。改稿走三条回路，由人决定，脚本只报数。
- **跨书风格同构的自动拦截**：只做了 `骨架体检.py --compare`（拍序列对比），没做"两本书读起来像一个作者"的整体判定——那需要人工对照，脚本只给拍序列与密度。
