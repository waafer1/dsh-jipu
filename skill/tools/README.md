# 工具清单（16 个，全部实装且带自检）

> **一条纪律**：这份表就是全部。手册里点到而这张表里没有的脚本，是死链，发现就删引用或补脚本——**不许留着让成员去跑一个不存在的命令**。

## 怎么进项目

`08_工具_脚本/开项目.py <书名>` 会把本目录 14 个脚本整套复制到新项目 `08_工具_脚本/`。
已有项目缺脚本：把本目录 `*.py` 复制进去即可。**不要**让 agent 直接调用技能目录里的脚本当项目脚本——项目内那份才是唯一入口（路径固定、审计可复现）。

**运行位置**：一律在**项目根目录**下跑。`选型体检.py`／`能力自测.py`／`账本体检.py` 不带参数，靠当前目录向上找 `项目配置.json`；在技能目录或别的书目录里跑，会报"读到 0 行""找不到根"——那是跑错地方，不是稿子有问题。要么先 `cd` 到项目根，要么显式给路径（`--file`／`--root`）。

## 三条使用纪律

1. **换机器先跑 `--selftest`。** 十四个脚本都带自检；自检不过就别拿它判稿——坏工具判出来的"通过"比没有更糟。
2. **脚本是下限，不是上限。** 它们只抓语法层和可数的症状；"这一段有没有画面""读者会不会划走"必须人判。任何一次"脚本 PASS 但读起来要跳"，以人判为准，并把那条规则标成待修。
3. **改脚本要改这三处**：本表、`references/03-门禁手册.md` 的命令表、相关 agent 的必跑命令。三处不一致，成员会照着旧命令跑空。
