# 05 · 状态、追踪与评审

> 出处：`01_法则_章法节奏爽点/流水线.md` 第 8—9 步、`06_追踪_状态账本/上下文.md`（派生视图）、`05_质检_审计评审节奏/评审/第003章_评审.md`（骨架样例）。

## 一、追踪目录各管什么

| 文件 | 是什么 | 谁写 |
|---|---|---|
| `_tracking-state.json` | **唯一事实源**：账、线、伏笔、人物、事实、拍点 | 记忆体，一章一提交 |
| `上下文.md` | **派生视图**：他在哪、手上有什么、欠谁、还剩几天、本章变了什么、下章要接的三件事 | 由 state 重渲染，**不许手改** |
| `事实词典.md` | **派生视图**：钱、物价、规矩、名词口径（源 `facts`） | 由 state 重渲染，审计时补 |
| `伏笔.md` | **派生视图**：开口的线（`threads`）＋未回收伏笔（`foreshadows`，A/B 两级） | 由 state 重渲染 |
| `数字登记.md` | 正文里出现过、但不在价目表上的数字（年龄、年数、人头分布、修辞）＋理由 | 审计时补；数字体检对不上时也写这里 |
| `桥段账本.md` | 用过的桥段与冷却章（同一手法一章一次，隔三章才准再用） | 细纲阶段查，提交阶段更 |
| `召回_第NNN章.md` | `召回.py --write` 生成的旧账注射包 | 备料阶段 |
| `能力自测报告.md` | 九环节达标率（`能力自测.py --write`） | 换项目时重跑 |

## 二、state 结构（照着填，别加字段）

```json
{
  "state_revision": 4,
  "last_committed_chapter": 3,
  "committed_at": "2026-10-31",
  "commit_note": "012《试丹》落地：……",
  "threads": [ { "id": "T01", "name": "…", "status": "open|closed", "due": "一天", "note": "…" } ],
  "foreshadows": { "F01": { "tier": "A|B", "summary": "…", "progress": "001…；002…；003…", "status": "open|paid" } },
  "characters": { "<主角名>": { "role": "…", "cash_copper": 511, "status": "…", "relation": "…", "note": "…" } },
  "facts": {
    "prices_used": { "…": "…" },
    "rules_established": { "…": "…" },
    "goods": { "…": "…" },
    "chapter_N_numbers": { "…": "…" }
  },
  "beats": { "003": ["交底：…", "碰壁：…", "…"] }
}
```

## 三、提交动作（记忆体做，不外派给作者）

1. `state_revision` +1，`last_committed_chapter` 改成本章号，`committed_at` 写日期，`commit_note` 一句话写清本章落地了什么（带数）。
2. 更新 `threads`（到期、开新线、关旧线）、`foreshadows`（在 `progress` 里追加本章进展，兑掉的改 `paid`）、`characters`（现金、伤、关系、池子几成）、`facts`（新价、新规矩、新货、本章数字）、`beats[本章号]`（8 条左右，一句一拍）。
3. 重渲染五份派生视图（按现有文件的节结构，不许改节名）：
   - `上下文.md`：①他现在在哪 ②他手上有什么 ③他欠谁 ④他还剩几天 ⑤这一章之后变了什么 ⑥本章要接的三件事；开头一行写 `state_revision` 与重建依据。
   - `事实词典.md`：从 `facts` 铺表（钱／物价／规矩／名词），每条带出处章号。
   - `伏笔.md`：开口的线 ＋ 未回收伏笔（A 级＝来源未解释，B 级＝方法未兑现）。
   - `数字登记.md`：追加本章不在价目表上的数。
   - `桥段账本.md`：追加本章用过的桥段与冷却到的章号。
4. 报一句：**"state_revision N，已提交第NNN章"**。

> 本项目**没有 state-commit / render 脚本**。`01_法则_章法节奏爽点/流水线.md` 第 9 步提到的 `state-commit`＋`render` 是外部工具，本机未落地——手工做上面的五步。

## 四、评审报告骨架

照 `05_质检_审计评审节奏/评审/第003章_评审.md`：

```
# 第NNN章《标题》· 读者评审

> 读者画像：魔兽老玩家，28—40，读过网文，最烦"主角挨打十章"。
> 读过的东西：正文全文；细纲；审计；文风基准。

## 一、打分        开篇抓力／爽点兑现／人物可信／语言／连续性 各 20 分 + 总 100 + 一句定性
## 二、逐句六问（抽最险的）   1—6 条，每条带行号与判
## 三、孤岛对白判定
## 四、弃读点       位置% ／为什么想划走／为什么留着／风险／判（保留|压掉|改）
## 五、爽不爽（对爽点宪法）   可数奖励／在场反应／代价／缺的
## 六、给下一章的硬要求     3—5 条，带数
```

## 五、复盘的周期

- **一章**：三份报告 + 章检。
- **一段（15 章）**：章目连读三问——①15 个章名能不能一句话说完 ②第 1 章与第 15 章之间他多了什么 ③有没有两章在干同一件事。过不了不许开下一段（样例：`05_质检_审计评审节奏/审计/章目体检_2026-10-31.md`、`05_质检_审计评审节奏/审计/复盘_大纲_2026-10-31.md`）。
- **一卷（75 章）**：跳一大档是否兑现、资源带是否上档、真背叛是否发生、四样是否已换（定价对象／赢法／背叛者身份／主角的面孔）。

## 六、交付话术（给作者）

```
第NNN章《标题》
- 句检 blocking 0 ／ advisory N
- 宾语盘点 N 条，改 M 处
- 对白占比 0.xx ／ 最长纯叙 N 字
- 数字回代 N 项，0 处对不上
- 章检：三项全 PASS
- 读者判定：三项 PASS（存兑／聚焦／钩子）／WARN N
- 文件：04_正文_成品/… ｜ 05_质检_审计评审节奏/审计/… ｜ 05_质检_审计评审节奏/节奏/… ｜ 05_质检_审计评审节奏/评审/…
```

不下结论式夸奖，只给读数与"过／不过"。
