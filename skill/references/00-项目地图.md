# 00 · 项目地图

> 用来回答两个问题：**这条规矩写在哪？** 和 **这本书现在是什么状态？**
>
> 项目结构是九层（`00`—`08`）。旧路径（`大纲/`、`设定/`、`正文/`…）一律作废，见到即换算成下表新路径。
>
> **本文件不写任何一本书的内容与进度。** 每一本书的文件清单和进度都不一样，写进来就会过期、串味、误导后来的 agent。要进度，现读 `_tracking-state.json`；要清单，现跑 `ls`。

## 二、九层速查（每层放什么，不列具体文件）

```
00_底座_语文能力/     句子与语感：句法基准、文风基准、环境锚点库、语文知识、画面例句库
01_法则_章法节奏爽点/ 规矩：爽点宪法、节奏铁律、章施工标准、章名规范、三把尺子、流水线
02_设定_世界与角色/   世界与人物：题材定位、世界现状、金手指、canon/（正典数值）、角色/、素材/
03_图纸_大纲与细纲/   图纸：总纲、卷纲、章纲、细纲_第NNN章
04_正文_成品/         稿子：第NNN章_<章名>.md
05_质检_审计评审节奏/ 验收：审计/、节奏/、评审/（按章一份）
06_追踪_状态账本/     记住：_tracking-state.json ＋ 上下文／事实词典／伏笔／数字登记／桥段账本
07_模板_复用件/       复用：引导式选型、细纲／正文／审计模板、类目模板库、剧情模板库
08_工具_脚本/         机器：句检、句病检、对白归属、数字体检、章体检、章检、画面检、召回、读者判定、开项目
```

**系统层 vs 项目层**：`00`＋`01`＋`07`＋`08` 是通用底座（换书照用）；`02`—`06` ＋ `项目配置.json` 是**这本书自己的资产**（换书不带走）。判据：一条规则若提到具体人名、地名、物名、书名，它就是项目层的。开新书见 `references/06-系统与开新书.md`。

## 三、进度：不写在这里

进度只有一个来源——`06_追踪_状态账本/_tracking-state.json` 的 `last_committed_chapter`。文件目录里的篇数、`00-索引.md` 的看板、任何笔记里的"写到第几章"，都**不作数**。

理由：进度是会变的，写进地图就会过期；过期地图比没有地图更坏——agent 会拿它当现状开工。
